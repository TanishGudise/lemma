A **monitor** is a check you declare for one project and one named agent. It judges whether that agent’s traces fit what you described. Open **Monitors** in a project in the [Lemma dashboard](https://platform.uselemma.ai).

## Groups

**All monitors** lists every monitor in the project. **New group** adds a tab you name. A monitor can sit in more than one group, and it always stays in **All monitors**.

Right-click a group to rename it, add monitors, or delete the group. Deleting a group leaves its monitors running. Inside a group, **Add existing** puts monitors you already have into that tab. A monitor you create while that tab is open starts in the group too.

Drag a card to change its order in the open tab.

One board per project stores the groups, which monitors they hold, and the **All monitors** card order. The dashboard saves that board for the project. A reload, or another member of the project, sees the same groups, membership, and card order. Deleting a monitor removes it from the groups and from the card order. On a monitor, the side rail lists its groups, or **No group yet**.

## Signal versus behavior

You choose the kind when you create the monitor. It does not change later.

In the dashboard, **New monitor** asks for the agent, then one of these:

- **Signal**: whether a trace fits. It does not write issues.
- **Behavior**: you give it a name and how the agent should behave. When a trace fits, it writes issues for this monitor only.
- **Template**: one monitor for each starter you pick.

**Existing** appears only inside a group.

Those issues are separate from failures Lemma groups on its own. Alerting still follows the [issue lifecycle](/platform/issues).

### Create

The name field can suggest tools this project has already called, and that text is the monitor’s name. A behavior monitor does not store a separate tool name. Learning does not search for a call named like the title. It searches retained traces for that agent and decides which calls fit.

The behavior you write, and an optional hint on a signal monitor, are used only while learning. Later reads do not return that text.

## One agent

Each monitor watches one agent. `agent_name` is the agent name on the trace, the same value as `gen_ai.agent.name`. You set it at create. Lemma stores it as given, and later edits cannot change it.

Lemma does not judge a trace that has no agent name. A monitor never judges another agent’s traces. The dashboard lists agent names this project has already sent, and the list can filter to one of them. **All agents** shows every monitor. See [Traces](/platform/traces) and the [trace contract](/reference/trace-contract).

## Daily percent and count

<Frame>
  <img src="/images/platform/monitors-detail.png" alt="Rate Binder monitor with a daily percent chart, a Count toggle, and the Quoting group" />
</Frame>

The chart is one point per day. **Percent** is the share of that day’s traces that fit. **Count** is how many traces fit. A behavior monitor also shows how many of those traces have an occurrence. Until the monitor has seen a trace, there is no percent yet.

You can also view the same chart by week or by month. The window includes the start and leaves out the end. Reads already apply include and exclude corrections.

## Recalibrate

Lemma learns from your feedback every night. **Recalibrate** starts that pass now. A night with no new feedback skips. If a run is already in progress, Lemma refuses another recalibrate.

A wording change stays a suggestion until you accept it. Dismiss a suggestion to keep the saved wording. Recalibrate does not rescore traces that already have a result.

## Include and exclude

**Doesn’t fit** and **Mark incorrect** both record `exclude`. **Add to monitor** records `include`, including a trace the monitor has not judged. You can attach a short reason. On the monitor’s **Traces** and **Issues** tables, **Mark incorrect** is the whole first cell, and you can mark several rows at once.

`exclude` drops the trace from the fit count, the chart, and the trace list. `include` puts the trace on those reads. **Undo**, or **Restore** on the **Feedback** tab, returns the trace to the monitor’s own judgment. One monitor keeps one active correction per trace.

## Learning and feedback

Learning searches traces Lemma still retains for that agent. Those traces stay on the [Traces](/platform/traces) list for 14 days. After you create a monitor, the chart fills in as those traces are judged.

The **Feedback** tab lists your corrections. The next recalibrate uses corrections recorded after the last succeeded run started, including the reason when you wrote one. A succeeded run removes the feedback it used. A failed or skipped run leaves that feedback in place.

## From the API

REST and the [Lemma Model Context Protocol (MCP) server](/connections/mcp) share the monitor reads. Creating a monitor, changing it, recording feedback, and recalibrating stay on REST. Request shapes are in the [API Reference](/api-reference).
